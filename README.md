# Sort Algorithms

Wikipediaの「[ソート](https://ja.wikipedia.org/wiki/%E3%82%BD%E3%83%BC%E3%83%88)」に記載されたソートアルゴリズムから2つを選んでRubyで実装した。

## 実装したソート

- 挿入ソート（Insertion sort）
- マージソート（Merge sort）

## それぞれのソートの良かった点

### 挿入ソート

配列の値を1つずつ取り出して、左隣と比べながら正しい場所まで動かす。やっていることがシンプルなので、コードを読めば動きがそのまま頭に入ってくる。

ほぼソート済みの配列だとすぐ終わるのも強み。左隣が自分以下になったら止まる仕組みのため、すでに並んでいる部分は数回の比較で済む。

ただし、データが増えると比べる相手も増えるので、急激に遅くなる。要素が2倍になると処理時間は約4倍。大量のデータには向かない。

配列の中で値を入れ替えるだけで処理が完結するので、追加のメモリが要らないのも良い点。マージソートのように途中で別の配列を作る必要がなく、要素数がいくら増えても使うメモリの量は変わらない。

### マージソート

データが増えても急激には遅くならないのが強み。配列を半分、また半分と分けていく構造になっているため、データが大きくなっても分割の段数は少しずつしか増えない。たとえばデータが1000個なら分割は10回ほど、100万個でも20回ほどで済む。挿入ソートのように「全部の要素 × 全部の要素」の比較にはならず、大量のデータでも安定して速い。

入力の並び方に関係なく一定の速さで動くのも利点。挿入ソートのようにデータがバラバラだと急に遅くなる、ということがない。

## 処理速度の実測

`benchmark.rb` でランダムな配列をソートして処理時間を計測した。

| 要素数 | 挿入ソート | マージソート |
|---|---|---|
| 100 | 0.12 ms | 0.08 ms |
| 1000 | 9.2 ms | 1.1 ms |
| 10000 | 913 ms | 9.8 ms |

要素数が10倍になるたびに挿入ソートは約100倍遅くなっていく一方、マージソートは10倍ちょっとずつしか伸びない。要素数1万の時点で、両者の差は約90倍まで開いていた。データが大きくなるほどマージソートの優位が広がることが、実測でも確認できた。
